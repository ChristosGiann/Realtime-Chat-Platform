# Ασφαλείς επαναλήψεις αποστολής — #42

Το POST `/api/conversations/{conversationId}/messages` απαιτεί πλέον JSON
`{ "clientMessageId": "UUID", "body": "κείμενο" }`. Ο client δημιουργεί νέο τυχαίο
UUID για κάθε νέα λογική αποστολή και κρατά το ίδιο UUID, σώμα και συνομιλία όταν
επαναλαμβάνει την αποστολή μετά από timeout ή απώλεια απάντησης. Το κλειδί δεν
αντικαθιστά την ταυτότητα χρήστη ή το CSRF token. Απουσία, null, μη έγκυρο UUID
ή Guid.Empty επιστρέφουν 400 χωρίς εγγραφή.

- Πρώτη αποστολή: 201 μετά το commit.
- Ίδιο κλειδί, authenticated sender, conversation και ακριβώς ίδιο body: 200 με
  το αρχικό DTO, ίδιο id και UTC createdAt. Δεν αλλάζει το μήνυμα.
- Ίδιο κλειδί με διαφορετικό sender, conversation ή body: 409 ProblemDetails,
  χωρίς αποκάλυψη του αρχικού μηνύματος. Η σύγκριση σώματος είναι ακριβής,
  χωρίς trimming, αλλαγή πεζών/κεφαλαίων ή Unicode normalization.
- Διαφορετικά κλειδιά με ίδιο body είναι διαφορετικές νόμιμες αποστολές.

Ο έλεγχος τρέχουσας συμμετοχής προηγείται κάθε αναζήτησης κλειδιού: αφαιρεμένο
μέλος δεν αποκτά πρόσβαση μέσω retry (404). Ισχύουν κανονικά session/CSRF validation
και no-store. Το DTO περιλαμβάνει clientMessageId για συσχέτιση με την αποστολή.

Η PostgreSQL είναι source of truth. Το ClientMessageId είναι NOT NULL, μη κενό
και παγκοσμίως μοναδικό στον πίνακα Messages. Η καθολική μοναδικότητα δίνει σαφές
409 και για λάθος επαναχρησιμοποίηση σε άλλη συνομιλία ή από άλλο χρήστη. Τα UUID
είναι τυχαία αναγνωριστικά, όχι μυστικά διαπιστευτήρια. Δεν υπάρχει TTL ή προσωρινή
cache: η δέσμευση διαρκεί όσο το μήνυμα.

Το υπάρχον conversation row lock σειριοποιεί ταυτόχρονες αποστολές στην ίδια
συνομιλία και διατηρεί τη συνέπεια με membership mutations. Μεταξύ διαφορετικών
συνομιλιών το unique index είναι ο τελικός διαιτητής: μόνο η συγκεκριμένη unique
violation μετατρέπεται σε 409 μετά από rollback. Άλλες αποτυχίες δεν κρύβονται.
Οι writers οφείλουν να ακολουθούν το ίδιο πρωτόκολλο. Απευθείας εξωτερικό SQL που
παρακάμπτει το row lock προστατεύεται από uniqueness, αλλά μπορεί να προκαλέσει
409 αντί για 200 στο συγκεκριμένο concurrent retry· επόμενο retry διαβάζει το row.

Η migration προσθέτει αρχικά nullable column, γεμίζει ξεχωριστό gen_random_uuid()
στα προϋπάρχοντα μηνύματα και κατόπιν επιβάλλει NOT NULL, CHECK και unique index.
Τα ιστορικά δεδομένα διατηρούνται. Τα backfilled UUID δεν ανακτούν παλιά client
requests που δεν είχαν κλειδί. Δεν υπάρχει μόνιμο database default για νέες εγγραφές.
Downgrade αφαιρεί τα κλειδιά· επόμενο upgrade δημιουργεί νέα, συνεπώς χάνεται η
παλιά αντιστοίχιση retries. Το deployment απαιτεί αναβάθμιση clients στο νέο συμβόλαιο.

Τα PostgreSQL/Testcontainers tests καλύπτουν ταυτόχρονες ίδιες αποστολές,
διαφορετικές συνομιλίες, ασφαλή retries, συγκρούσεις περιεχομένου/ταυτότητας,
ανάκληση συμμετοχής, validation, απευθείας database constraints και upgrade με
υπάρχοντα μηνύματα. Δεν προστίθενται SignalR deduplication, offline queues,
history API, frontend send flow ή γενική υποδομή request IDs.
