# Frontend προφίλ και αναζήτησης — issue #10

Οι συνδεδεμένοι χρήστες βρίσκουν την επεξεργασία στο /#/profile και την αναζήτηση
στο /#/users. Η δημόσια σελίδα /#/profiles/{userId} λειτουργεί και χωρίς συνεδρία,
ακόμη και αν αποτύχει η ανάκτηση του /api/auth/me.

Η φόρμα προφίλ στέλνει μόνο displayName, bio και avatarUrl με PUT /api/profiles/me,
μαζί με νέο CSRF token. Τα κενά προαιρετικά πεδία γίνονται null. Ο server παραμένει
υπεύθυνος για ownership και validation. Τα σφάλματα εμφανίζονται δίπλα στα πεδία,
η επιτυχία ανακοινώνεται και τα νέα στοιχεία ενημερώνουν την κοινή κατάσταση χρήστη.
Απάντηση ενημέρωσης άλλης παλιότερης συνεδρίας δεν ενημερώνει τον τρέχοντα χρήστη.

Το δημόσιο προφίλ και τα αποτελέσματα αναζήτησης εμφανίζουν μόνο δημόσια στοιχεία.
Το bio αποδίδεται ως απλό React text με διατήρηση αλλαγών γραμμής, χωρίς HTML.
Το HTTPS avatar URL παρέχεται ως σύνδεσμος με noopener/noreferrer, ώστε να μη
γίνονται αυτόματα αιτήματα προς τρίτους. Δεν υπάρχει upload αρχείου.

Η αναζήτηση γίνεται με ρητή υποβολή. Αρχική, κενή, loading, no-match και error
κατάσταση διακρίνονται. Το κουμπί «Περισσότερα αποτελέσματα» μεταφέρει τον opaque
cursor με URL encoding και προσθέτει αποτελέσματα. Νέα αναζήτηση καθαρίζει τον
cursor/λίστα, ενώ αποτυχία επόμενης σελίδας διατηρεί τα προηγούμενα αποτελέσματα
για retry. AbortController ακυρώνει αιτήματα όταν ξεκινά νέα αναζήτηση ή αλλάζει
η σελίδα. Το UI αποτρέπει διπλή υποβολή και διπλότυπα αποτελέσματα.

Protected API 401 καθαρίζει τη συνεδρία και εμφανίζει σύνδεση. Η δημόσια προβολή
έχει φόρτωση, 404/σφάλματα και retry. Το API παραμένει η πηγή εξουσιοδότησης.

Έλεγχοι: npm run lint, npm run build, npm run test:ui. Προστίθενται έξι browser
σενάρια με mocked API για profile update/validation, public privacy/escaping,
pagination/reset, session expiry και error/retry. Ο πραγματικός έλεγχος API/DB
θα εκτελεστεί στο #11. Οι περιορισμοί της αναζήτησης περιγράφονται στο user-search.md.
